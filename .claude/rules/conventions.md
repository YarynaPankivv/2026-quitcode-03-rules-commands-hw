# Конвенції коду lead-sync

## Контекст

Конвенції з `materials/architecture-brief.md` — не стиль, а механіка: вони дають
таймаути й повтори в HTTP, маскування секретів у журналі й помітність пошкоджених
даних. Кожен пункт нижче перевіряє `npm run check:rules`, і зараз він показує
`TOTAL: 0 violation(s)` — увесь спадковий код уже приведено до конвенцій. Тому
будь-яке порушення у звіті внесене твоїми змінами.

## Правило

- **Помилки — значення.** Функція, що може не вдатися, повертає `Result<T>` з
  `core/types.ts`. Не кидай винятків назовні модуля: `send()` інтеграції завжди
  повертає `Result<void>`, а не `throw`. Зовнішній виняток лови на місці й
  повертай `{ ok: false, error: "..." }`.
- **HTTP — лише `postJson()`** з `app/src/core/http.ts`. Не використовуй прямий
  `fetch` (у ньому немає таймауту, повторів на 5xx/429 і маскування URL) і не
  додавай axios, got чи ky.
- **Змінні середовища — лише `readEnv(name)`** з `app/src/core/config.ts`. Не
  читай `process.env` поза ядром. Значення секретів не логуй і не вшивай у код
  навіть тимчасово — передавай `readEnv(...).value` одразу в `postJson`.
- **Зовнішній текст — лише `parseJson(text, guard)`** з `app/src/core/parse.ts`,
  з guard на очікувану форму (`isRecord`, `isString`, `isNumber`). Не викликай
  `JSON.parse` напряму. Невалідний JSON або несподівана форма — це
  `{ ok: false, error }`, який видно в журналі; не підставляй «значення за
  замовчуванням» і не продовжуй роботу мовчки — так пошкоджені дані стають
  непомітними.
- **Журнал — лише `log.info` / `log.warn` / `log.error`** з `app/src/core/log.ts`.
  Не використовуй `console.*` поза ядром: `log` маскує токени, `console.log`
  друкує їх як є.
- **Без `any`.** Для невідомих даних — `unknown` плюс guard; замість `as any` —
  звужуй тип guard'ом. Це стосується й `catch (error)`: перевіряй
  `error instanceof Error`.
- **Без нових залежностей.** У `app/package.json` нуль runtime-залежностей, і так
  має лишитись. Не запускай `npm install <пакет>`; потрібна бібліотека — спершу
  питання в PR. Дозволені імпорти — відносні шляхи й `node:*`.
- **Мінімізація даних.** У сповіщення (Slack, месенджери) не передавай
  `lead.email` і `lead.phone` — лише `name`, `source`, `budgetUsd`. Повні дані
  йдуть тільки в системи обліку: таблиця, CRM.
- **Імена.** Файли — kebab-case; поле `name` інтеграції збігається з іменем файлу.
- **Тести.** Vitest, `<модуль>.test.ts` поруч із модулем, без реальної мережі:
  `vi.stubGlobal("fetch", ...)` і `vi.stubEnv`. Для кожної інтеграції — успішна
  відправка (звір URL і тіло запиту), відсутня змінна середовища, помилка від
  зовнішньої системи.
- **Спадковий код** переписуй окремою задачею і **без зміни поведінки**: URL,
  тіло запиту й тексти помилок лишаються ті самі, асерти в наявних тестах не
  редагуй.

## Як перевірити

- `cd app && npm run check:rules` → `TOTAL: 0 violation(s)`; будь-який ненульовий
  рядок у розділі `by rule` вказує на твою зміну.
- `cd app && npm test` → зелено; `cd app && npm run typecheck` → без помилок.
- `git diff app/package.json` → секція `dependencies` не з'явилася.
- У каналах сповіщень немає особистих даних:
  `grep -n "lead.email\|lead.phone" app/src/integrations/slack-notify.ts app/src/integrations/telegram-notify.ts`
  → порожньо. Для систем обліку (таблиця, CRM) повні дані навпаки очікувані.
